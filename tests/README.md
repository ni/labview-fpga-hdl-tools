# Test Architecture

## Overview

The test suite validates `nihdl` CLI commands by running them against a self-contained
sample project, then comparing generated outputs against checked-in reference files.
All tests run with `skip_vivado` and `skip_modelsim` enabled so no external tools
are required.

## Folder Layout

```
tests/
├── test_workflow.py              # Test runner (the only file you execute)
├── test-project/                 # Input: sample project mimicking a real FlexRIO target
│   ├── deps/                     # Mock dependency tree (CLIP XML, HDL sources)
│   └── targets/
│       ├── common/               # Shared assets (menus, templates)
│       └── pxie-7903/            # The target under test
│           ├── nihdlsettings.py          # Primary settings (all features enabled)
│           ├── badsettings.py            # Intentionally invalid paths (error tests)
│           ├── nowindowsettings.py       # No lvWindowNetlist (optional-feature test)
│           ├── lvWindowNetlist/          # Checked-in Window netlist files
│           ├── lvFpgaTarget/             # Target plugin templates & inputs
│           ├── rtl-lvfpga/               # Mako templates for HDL generation
│           ├── xdc/                      # Constraint templates
│           └── TCL/                      # TCL script templates
├── test-project-expected/        # Reference: expected generated outputs
│   └── targets/pxie-7903/
│       ├── objects/              # Expected contents of objects/ after commands run
│       └── VivadoProject/        # Expected Vivado project files
├── test-plugin-install-dir/      # Output: where install-target writes (generated)
├── test-plugin-install-dir-expected/  # Reference: expected install-target output
├── test-vivado/                  # Stub: fake vivado.bat (prints nothing, exits 0)
├── test-modelsim/                # Stub: fake vsim.exe
└── test-labview-vpe/             # Stub: fake LabVIEW VPE export (for get-window)
```

## Key Concepts

### Input vs Output vs Expected

| Folder | Committed? | Purpose |
|--------|-----------|---------|
| `test-project/` | Yes | Inputs that the commands consume. Never modified by tests. |
| `test-project/targets/pxie-7903/objects/` | No (.gitignore) | Generated outputs. Cleaned before each test run. |
| `test-project-expected/` | Yes | Golden reference files to compare against. |
| `test-plugin-install-dir/` | No (.gitignore) | Generated by `install-target`. Cleaned before each run. |
| `test-plugin-install-dir-expected/` | Yes | Golden reference for install-target output. |

### Tool Stubs

Real Vivado, ModelSim, and LabVIEW are not available in CI. The settings files
point to stub directories (`test-vivado/`, `test-modelsim/`) that contain minimal
executables. Commands detect `skip_vivado=True` and skip the actual tool invocation,
but still validate settings, generate TCL scripts, and produce mock outputs.

### Settings Files

Each `.py` settings file exercises a different scenario:

- **nihdlsettings.py** — The primary config. Exercises all features: Window netlist,
  CLIP migration, constraint processing, HDL generation, target plugin, etc.
- **badsettings.py** — Invalid paths and missing settings. Every command should fail
  with a controlled error (exit code 1, no unhandled traceback).
- **nowindowsettings.py** — Omits `the_window_folder_input`. Verifies that commands
  gracefully skip Window-dependent logic.

### Output Validation Modes

The test runner compares generated outputs against expected references in two modes:

- **Exact match** — Used for `test-plugin-install-dir`. The output must contain
  exactly the same files with the same content. No extra files allowed.
- **Non-exact match** — Used for `test-project/objects/`. Expected files must match,
  but extra generated files (e.g., TCL scripts with machine-specific absolute paths)
  are allowed.

### Traceback Detection

Even when a command is expected to fail (exit code 1), an unhandled Python traceback
in stderr causes the test to fail. Commands must always fail gracefully with a printed
error message, never with an uncaught exception.

## Test Execution Flow

1. Clean `objects/`, `VivadoProject/`, `ModelSimProject/` directories
2. Run "No Error Tests" — all commands in sequence with the primary settings
3. Validate output folders against expected references
4. Clean again
5. Run "Expect Error Tests" — commands with `badsettings.py` (expect exit code 1)
6. Clean again
7. Run "No Window Folder Tests" — commands with `nowindowsettings.py`

## Maintaining the Test Fixtures

### When you add a new setting or feature

1. Add the setting to `nihdlsettings.py` (primary) with a valid value.
2. If the feature should fail gracefully when misconfigured, add a bad value
   to `badsettings.py`.
3. If the feature is optional, ensure it works when omitted (test via
   `nowindowsettings.py` or a new scenario file).

### When generated output changes

If your change alters the content of generated files (TCL scripts, XML, HDL, etc.):

1. Run `python tests/test_workflow.py` and confirm the command tests pass.
2. If output validation fails with "content mismatch", inspect the diff:
   - If the new output is correct, copy it to the corresponding `-expected` folder.
   - If it's wrong, fix the code.
3. Commit the updated expected files alongside your code change.

### When adding a new command

1. Add a test entry to `get_test_set_no_errors()` in `test_workflow.py`.
2. If the command produces files that should be stable, add expected files to
   `test-project-expected/`.
3. Add an error-case entry to `get_test_set_errors()` with `badsettings.py`.

### Adding new input data

If a new feature needs source files (HDL, XML, CSV, etc.), add them under
`test-project/`. Keep files minimal — just enough structure for the command to
parse and produce output. Do not copy large real-world files.

### The lvWindowNetlist folder

This folder contains checked-in Window netlist files that simulate what `get-window`
would extract from a LabVIEW Vivado Project Export. It includes:

- `CodeGenerationResults.lvtxt` — Required by `create-lvbitx`
- `TheWindowConstraints.xdc` — Parsed by `process_constraints` (must contain the
  three marker pairs: `BEGIN/END_LV_FPGA_PERIOD_CONSTRAINTS`,
  `BEGIN/END_LV_FPGA_CLIP_CONSTRAINTS`, `BEGIN/END_LV_FPGA_FROM_TO_CONSTRAINTS`)
- `*.vhd`, `*.v` — HDL files that get integrated into the Vivado project

When `the_window_folder_input` is not set, these files are ignored and the commands
operate without Window integration.
